# 講義レコーダー

日本語の大学講義を Windows のノートパソコンで録音し、**話している最中に先生の日本語をそのまま表示**しながら、終了後に**全文・概要・詳細要約・トピック別の要点・用語集・課題と締切・試験に出そうな項目・フラッシュカード・質問応答**までまとめて作るアプリです。

日本語の聞き取り精度を最優先にしています。ライブ字幕も録音後の精密文字起こしも、OpenAI で最も日本語に強い `gpt-transcribe` を使います。

- 録音・音声・書き起こし・ノートは**すべて自分のパソコンの中**に保存されます。
- 文字起こしと AI 生成のときだけ、音声とテキストが OpenAI に送信されます。
- **Wi-Fi が切れても録音は止まりません。** 音声はパソコンに書き込まれ続け、字幕だけが接続回復後に追いつきます。

## 1. 最初の準備（10 分）

### 手順

1. **Node.js** をインストールします（<https://nodejs.org/> の LTS 版、「Windows Installer」）。
2. ダウンロードした ZIP を**右クリック → プロパティ**。下に「**セキュリティ: このファイルは…ブロックされています**」と出ていたら「**許可する（Unblock）**」にチェックを入れて OK。
   - これをしないと、Windows が `start.cmd` を「安全でない可能性」としてブロックします。
3. ZIP を**右クリック → すべて展開**。展開先は `ドキュメント` など、ふつうのフォルダにします。
   - **ZIP の中身をダブルクリックしても動きません。** 必ず先に展開してください。
4. 展開したフォルダの中の `lecture-recorder` を開き、**`start.cmd` をダブルクリック**します。
   - 初回は `.env.local` がメモ帳で開きます。`OPENAI_API_KEY=` の右に自分のキーを貼り付けて保存し、メモ帳を閉じてください。
   - 準備に数分かかります。終わるとブラウザが開きます。
5. 2 回目以降も `start.cmd` をダブルクリックするだけです（<http://localhost:3939>）。

> 黒いウィンドウ（コマンドプロンプト）は**閉じないでください**。これがアプリ本体です。録音が終わり、ノートができてから閉じます。

### 毎回かんたんに起動する（おすすめ）

`setup-shortcut.cmd` を**一度だけ**ダブルクリックしてください。デスクトップに「講義レコーダー」のアイコンができます。次からはそれをダブルクリックするだけです。

- そのアイコンを**タスクバーにドラッグ**すると、タスクバーからも起動できます。
- 実行中に「Windows のサインイン時に自動起動しますか？」と聞かれます。`y` を選ぶと、パソコンを起動するだけでアプリが立ち上がり（画面は最小化）、授業前は<http://localhost:3939>を開くだけになります。ブラウザのお気に入りに入れておくと便利です。
- もう一度 `setup-shortcut.cmd` を実行すると、自動起動の解除もできます。
- すでに起動している状態でアイコンを押しても、二重に起動せずブラウザが開くだけです。
- アプリのフォルダを移動したときは、`setup-shortcut.cmd` をもう一度実行してください。

### 最新版に更新する

`update.cmd` をダブルクリックするだけです。ZIP を落として展開し直す必要はありません。

- 先に**アプリの黒い画面を閉じて**ください。起動したままだと更新できません（そう表示されます）。
- 最新版のダウンロード → ファイルの入れ替え → 準備までを自動で行います。数分かかります。
- **録音・全文・ノート・API キーは消えません。** 音声とノートは別のフォルダ（下記「保存場所」）にあり、API キーを書いた `.env.local` は更新の対象外です。
- `add-subjects.ps1` を自分の時間割に書き換えている場合は、`add-subjects.前回.ps1` として残します。
- 終わったら `start.cmd` かデスクトップのアイコンで起動してください。

### ビルド中に「Application Control policy has blocked this file」と出る場合

Smart App Control が Next.js の高速コンパイラ（`next-swc...node`）をブロックしています。**エラーではありません。** Next.js は自動的に WebAssembly 版のコンパイラに切り替えて処理を続けます。

- 待っていれば完了します。初回のビルドが数分長くなるだけで、**アプリの動作と精度は変わりません**。
- ビルドは最初の 1 回だけです。2 回目以降の起動（`npm start`）では発生しません。
- **Smart App Control は無効にしないでください。** 一度切ると Windows を初期化するまで戻せません。高速コンパイラのために切る価値はありません。

### フォルダの場所（重要）

`ダウンロード` の中の、名前が長いフォルダが二重になった場所のままだと、Windows のパス長制限（260 文字）に引っかかってビルドが失敗することがあります。

うまくいかないときは、フォルダごと短い場所に移してからやり直してください。

```
C:\lecture-recorder
```

移したあとは、そのフォルダで `npm run build` を実行し直します。

### 「Smart App Control がブロックしました」と出る場合

手順 2 の「許可する」をしていれば、ふつうは出ません。それでも出るときは、`start.cmd` を使わずに直接起動できます。**Smart App Control を無効にしないでください**（一度切ると、Windows を初期化するまで戻せません）。

1. `lecture-recorder` フォルダを開きます。
2. 上のアドレスバーをクリックし、`powershell` と入力して Enter。
3. 開いた青い画面に、次を 1 行ずつ貼り付けて Enter します。

```powershell
Get-ChildItem -Recurse | Unblock-File
Copy-Item .env.example .env.local
notepad .env.local
```

4. メモ帳が開いたら `OPENAI_API_KEY=` の右にキーを貼り付け、保存して閉じます。
5. 青い画面に戻り、続けて次を実行します（1 回目は数分かかります）。

```powershell
npm install
npm run build
npm start
```

6. ブラウザで <http://localhost:3939> を開きます。次回からは `npm start` だけで起動します。

### 授業の前に確認すること

- 外部マイクを**先に挿してから**「録音する」画面を開き、「マイク」欄で選び直す。
- 設定 → システム → 電源とバッテリー →「画面とスリープ」で、**電源接続時のスリープを「なし」**にする。画面が暗くなるだけなら録音は続きますが、スリープに入ると止まります。
- AC アダプターをつなぐ。
- 「録音を開始」を押したら、**録音タブは開いたまま**にする（他のタブを見るのは問題ありません）。

## 2. 使い方

### 科目を作る

ライブラリ →「＋ 科目を追加」。科目名・担当教員・講義の言語（日本語／英語）を入れます。

**専門用語**の欄が精度の要です。`知覚価値、STP、限界効用` のように、その授業で出る用語を入れておくと、音声認識のヒントとして使われ、表記も統一されます。シラバスや教科書の目次から写しておくのがおすすめです。

### 科目をまとめて登録する

科目が多いときは、付属の `add-subjects.ps1` を使うと一度に登録できます。ファイルを開いて `$subjects` の部分を自分の時間割に書き換え、右クリック →「PowerShell で実行」。アプリを起動した状態で実行してください。

### 録音する

「録音する」→ 科目を選ぶ →「録音を開始」。

- **先生の日本語**が約 15 秒ごとに増えていきます。日本語は述語が文末に来るので、区切りを短くすると文が途中で切れて精度が落ちます。既定の 15 秒を推奨します。
- 入力レベルのバーが動いているか確認してください。ほとんど動かない場合はマイクの選択が違います。
- **予約開始**に時刻（例 `13:00`）を入れておくと、その時刻に自動で録音が始まります（この画面を開いたままにしてください）。
- **自動停止**（既定 95 分）で、止め忘れても勝手に終わります。

終わったら「**停止して書き起こす**」。ここから先は閉じても大丈夫です。処理はパソコンの中で続きます。

### スマホなどで録った音声を読み込む

ヘッダーの「**音声を読み込む**」から、スマホのボイスメモや IC レコーダーで録った音声ファイル
（m4a・mp3・wav・aac など）を読み込めます。録音したときと同じように、全文・要約・要点・
用語・課題・重要ポイント・フラッシュカード・質問応答まで作られます。ライブ字幕はありません。

**なぜ使うのか。** ノートパソコンの内蔵マイク（マイク配列）は、目の前の顔を拾うために作られて
います。100〜300 人の教室で 10 m 先の先生の声は、雑音として抑え込まれることすらあります。
スマホを机の上、できるだけ前の席に置いて録るほうが、はっきり録れます。

**おすすめの使い方は併用です。** 授業中はパソコンでいつもどおり録音し（ライブ字幕と自動処理が
効きます）、同時にスマホでも録っておきます。パソコン側の聞き取りが悪かったときだけ、スマホの
音声をここから読み込みます。もう一度出席することはできないので、保険になります。

- 音声は 16 kHz のモノラルに変換し、8 分ずつに区切って文字起こしします。変換はこのパソコンの
  ブラウザの中で行われ、元のファイルはそのまま保存されて講義のページで再生できます。
- 90 分の講義で、読み込みから送信までに数分かかります。その間はこの画面を閉じないでください。
  送信が終われば、あとは閉じても処理は続きます。
- 音量が小さすぎる録音は、読み込むときに警告が出ます。

### 重要ポイントの自動収集

先生が **「ここは試験に出します」「ここ重要です」「覚えておいてください」「締め切りは…」「間違えやすいので注意」** のように言った箇所は、**重要ポイント**タブに自動でまとまります。

- 録音中も、合図の語を含む字幕の行に **★** が付いて色が変わります。すぐ気づけます。
- 録音後、AI が前後の文脈を読んで「**何が**重要なのか」を書きます。「ここ」「これ」が指す中身まで特定します。
- **先生の発言をそのまま引用できたものだけ**を載せます。引用が書き起こしと一致しないものは捨てるので、作り話は入りません。
- 試験に出る／課題・締切／覚える／重要／間違えやすい の 5 つに分類され、絞り込みができます。
- 時刻をクリックすると、その場面の音声を再生して自分の耳で確認できます。
- 「テキストで保存」にもこの一覧が入ります。

合図の語だけで拾うと「実験」の聞き間違いなども混ざるため、最後は AI が「これは勉強の指示か？」を判断して落としています。それでも取りこぼしはあるので、試験前は全文タブも一度は目を通してください。

### 録音のあと

講義のページに 9 つのタブができます。

| タブ | 内容 |
| --- | --- |
| 概要・要約 | 3〜4 文の概要と、段落ごとの詳細要約 |
| 重要ポイント | 先生が「試験に出る」「重要」「覚えて」「締切」「注意」と言った箇所だけを自動で集めたもの |
| 要点 | トピック別の要点（音声の該当箇所へ再生ジャンプ）と復習問題 |
| 用語 | 用語・読み・意味・講義での使われ方の表 |
| 課題・試験 | 課題と締切／**先生が明言した試験範囲**と**AI の推測**を分けて表示 |
| 全文 | 時刻つきの全文。検索も可能 |
| フラッシュカード | ボタンを押したときだけ作成 |
| 質問する | この講義の内容について質問。講義にないことは「触れられていません」と答えます |
| 資料 | 講義スライド（PDF）やメモを追加すると、要約・用語・質問応答の根拠になります |

「テキストで保存」で、全部入りの 1 ファイル（Markdown）を書き出せます。

## 3. なぜ 90 分でも落ちないのか

録音中、マイクの音は**同時に 3 つの経路**に流れます。

```
マイク ─┬─ master : 連続録音。5 秒ごとにディスクへ追記（これが永久保存の音源）
        ├─ live   : 10 秒ごとの独立ファイル → すぐ文字起こし → ライブ字幕
        └─ pass   : 10 分ごとの独立ファイル → 録音後の「精密文字起こし」用
```

- **メモリに溜めません。** master は 5 秒ごとにファイルへ追記されるので、90 分でも 3 時間でもメモリ使用量は変わりません。強制終了しても失うのは最後の数秒だけです。
- **アップロード先は自分のパソコン**（localhost）です。大学の Wi-Fi が切れても、録音とディスクへの保存は影響を受けません。
- **精度は 2 段構え**です。ライブ字幕は 10 秒ごとに切るので速い代わりに、区切りで単語が割れます。録音後の精密文字起こしは 10 分単位でやり直すため、区切りが 1/60 に減り、前後の文脈も使えます。**最終的な全文・要約は、必ず精密側から作られます。**
- 文字起こしのあと、AI が**校正**します（同音異義語や専門用語の誤変換、句読点、「えー」などの除去）。内容の追加・要約はしません。聞き取れていない箇所は `［不明］` と残します。

### 音質と容量

既定は**モノラル 32 kbps（Opus）**。音声にはこれで十分で、90 分で約 **21 MB** です。10 回分でも 220 MB 程度。

「詳細設定」で 48 / 64 kbps に上げられますが、ファイルが大きくなるだけで文字起こしの精度はほぼ変わりません。大教室で後方に座る場合は、ビットレートより**マイクの位置**と**自動音量調整**のほうが効きます。

### 大教室（100〜300 人）向けの設定

- **ノイズ抑制はオフ**が既定です。通話向けの処理で、遠くの先生の声を環境音と判断して削ることがあるためです。
- **自動音量調整はオン**が既定。後方の席や小さな声に効きます。
- 指向性のある外部マイクを、できるだけ教壇の方向に向けてください。
- 精密文字起こしでは音量の正規化と音声区間の検出が行われるため、多少小さくても拾えます。

## 4. ハルシネーション（作り話）対策

「わからないことは、わからないと言う」ことを優先しています。

- 要約・要点・用語は、**書き起こしに根拠がある内容だけ**から作ります。一般常識での補完を禁止しています。
- **課題と締切**、**先生が明言した試験範囲**には、書き起こしからの**引用**が必要です。引用できないものは載せません。
- 試験に出そうな項目は「**先生が明言**」と「**AI の推測**」を別の欄に分けています。推測を先生の発言として書くことはありません。
- 聞き取れなかった箇所は消さずに「聞き取れなかった箇所」として一覧にします。
- 質問応答は書き起こしと資料だけを根拠にし、該当がなければ「この講義では触れられていません」と答えます。根拠にした時刻も表示します。

それでも音声認識の誤りは残ります。**重要な数字・締切・固有名詞は、全文タブの再生ボタンで実際の音声を確認してください。**

## 5. 保存場所とバックアップ

既定の保存先:

```
C:\Users\<ユーザー名>\LectureRecorder\
  courses.json
  lectures\<講義ID>\
    lecture.json      講義の情報
    audio\master.webm 音声（永久保存）
    live.jsonl        ライブ字幕
    transcript.json   精密な全文
    notes.json        ノート
    flashcards.json   フラッシュカード
    chat.jsonl        質問の履歴
    materials\        アップロードした資料
```

- **クラウドに残したい場合**は、`.env.local` に保存先を OneDrive のフォルダにすると自動で同期されます。

  ```
  LECTURE_DATA_DIR=C:\Users\<ユーザー名>\OneDrive\LectureRecorder
  ```

- 精密文字起こしが終わると、字幕用と精密用の作業ファイルは自動で消えます。残るのは `master.webm` だけです。

## 6. モデルが使えないとき

設定画面に「このアカウントでは次のモデルが使えないようです」と出た場合でも、そのまま使えます。文字起こしは自動的に `whisper-1` に、要約は使える別のモデルに切り替わります（講義ページに切り替えた旨が表示されます）。

切り替えなしで動かすには、`.env.local` に自分のアカウントで使えるモデル名を書いてください。

```
OPENAI_TRANSCRIBE_MODEL=whisper-1
OPENAI_LIVE_TRANSCRIBE_MODEL=whisper-1
OPENAI_LLM_MODEL=gpt-5
OPENAI_FAST_LLM_MODEL=gpt-5-mini
```

## 7. 困ったとき

| 症状 | 対処 |
| --- | --- |
| 字幕が出ない | 設定画面で API キーが読み込まれているか確認。キーを入れたら `start.cmd` を再起動 |
| 入力レベルが動かない | Windows のサウンド設定で入力デバイスと音量を確認 → 録音画面でマイクを選び直す |
| 途中で止まった | 音声は保存されています。講義ページの「文字起こしを実行」でやり直せます |
| 録音がスリープで切れた | 電源設定のスリープを「なし」に。それまでの音声は保存されています |
| 字幕が遅れる | 通信が遅いときは字幕が後追いになります。録音と最終的な精度には影響しません |
| 日本語が正しく聞き取れない | 録音画面の「音質」を 64000 にし、Windows のサウンド設定 → 入力 → マイクのプロパティで入力音量を上げてください。科目の「専門用語」欄に講義で出る用語を入れておくと、その表記で書き起こされます |
| 同じ文が何度も出る | 音声が小さい・不明瞭なときに起きます。同じ文の繰り返しは自動で除外されます |
| 字幕が飛ぶ（無音と判断される） | マイクの入力音量を上げてください。Windows のサウンド設定 → 入力 → マイクのプロパティ |
| PDF を読み取れない | 画像だけの PDF は文字を取り出せません。テキスト付きの PDF を使ってください |
| start.cmd がブロックされる | ZIP を展開していないか、ZIP の「許可する」をしていません。第 1 章の手順 2・3 を確認 |
| `npm` が見つからない | Node.js が未インストールです。インストール後、青い画面を閉じて開き直してください |
| ビルドが Application Control で止まる | エラーではありません。WebAssembly 版に切り替わって続行します。待てば完了します |
| ビルドが途中で失敗する | フォルダを `C:\lecture-recorder` のような短い場所に移して `npm run build` をやり直してください |
| ショートカットが動かない | フォルダを移動した可能性があります。`setup-shortcut.cmd` を実行し直してください |

## 8. 開発者向け

```bash
npm install
npm run dev        # http://localhost:3939
npm run build && npm start
npm run lint
npm run typecheck
npm test           # Vitest
```

構成:

```
app/
  page.tsx                    ライブラリ
  record/page.tsx             録音画面
  lecture/[id]/page.tsx       講義ページ（8 タブ）
  settings/page.tsx           設定
  api/…                       すべてローカルサーバー上の処理
components/                   画面
lib/
  recorder.ts                 3 本の MediaRecorder
  uploader.ts                 順序を保つアップロード
  api.ts                      ブラウザ側 API クライアント
  schemas.ts / export.ts      共通スキーマとテキスト書き出し
  server/
```
